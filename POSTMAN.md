# Дополнительная практика: Postman — +1 балл

Выполняйте после основного маршрута. Ориентир — 15–20 минут, если Postman уже установлен. Установка не должна отнимать время у обязательной практики.

Цель — проверить API отдельным клиентом и понять, какое поведение зависит от frontend.

## Подготовка

1. Оставьте локальный сервер запущенным. В приложении включите normal и сбросьте данные.
2. Откройте **Postman Desktop**. Для запросов достаточно lightweight API Client без входа в аккаунт. Не требуется создавать аккаунт или публиковать коллекцию.
3. Создайте новый HTTP-запрос.
4. Адрес по умолчанию: `http://localhost:3000`. Если вы выбрали другой порт, используйте его.

Не используйте облачный агент для обращения к своему localhost: адрес должен открываться с того же компьютера, где запущен сервер. Для этого маршрута используем desktop-приложение.

## 1. Получение списка

Выберите **GET**, URL `http://localhost:3000/applications`, нажмите **Send**.

Запишите статус, тип ответа и число объектов. Сравните со списком в браузере и контрактом.

## 2. Создание и последующая проверка

Выберите **POST**, URL `http://localhost:3000/applications`.

В **Body → raw → JSON** введите:

```json
{
  "name": "Алексей",
  "email": "alex@example.com",
  "topic": "html"
}
```

Проверьте наличие `Content-Type: application/json`. Отправьте запрос. Из ответа скопируйте id и сделайте отдельный GET по полному URL `/applications/этот-id`.

Сопоставьте поля с отправленными. Затем проверьте наличие записи в GET списка. JSON-пример задаёт форму запроса, собственные значения выберите сами.

## 3. Некорректный запрос

Запишите текущее число записей. Уберите обязательное поле или замените тему на неизвестную. Отправьте POST.

Ожидаются `400` и объект ошибки. Отдельным GET убедитесь, что запись не добавилась.

## 4. Воспроизведение нарушения API

Возьмите наблюдение из основной API-практики и повторите его через Postman с теми же исходными данными и режимом. Сравните запросы и ответы двух клиентов.

Если нарушение сохранилось, какая часть системы уже не нужна для его воспроизведения? Ответьте своими словами. Отсутствие расхождения в одном запросе ещё не доказывает исправность API.

## Необязательная коллекция

Если вы уже пользуетесь workspace Postman, можно импортировать `postman/workshop.postman_collection.json`. Она содержит заготовки без тестовых скриптов. Переменные коллекции:

- `baseUrl` — адрес вашего локального сервера;
- `applicationId` — id, который вы вручную скопировали из ответа POST.

В lightweight-клиенте выполните те же запросы вручную по инструкции выше. Импорт, экспорт и переменные коллекции не являются условием получения балла.

Официальная справка: [lightweight API Client](https://learning.postman.com/latest-v-12/docs/getting-started/basics/using-api-client), [составление запросов](https://learning.postman.com/docs/use/send-requests/requests/).
