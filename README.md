# Практика 1-7. Проверка перед открытием мастерской

Сегодня открывается запись на веб-мастерскую. Приложение выглядит готовым, но команда просит проверить его перед выпуском. Ваша задача — пройти пользовательские сценарии, проверить API отдельно и показать доказательства найденных проблем.

В стенде намеренно оставлены дефекты. Найти все за занятие не требуется. Важнее воспроизводимый отчёт и проверенное исправление.

Это практика на занятии. Домашнего задания в этом репозитории нет.

## Запуск за минуту

Нужен Node.js 22.12 или новее. В папке проекта:

```bash
node --version
npm start
```

`npm install` не нужен: внешних зависимостей нет.

Откройте **http://localhost:3000**. Один процесс обслуживает frontend и моковый API. Live Server и отдельный терминал для frontend не требуются.

Если порт занят:

```bash
npm start -- --port 3001
```

Тогда открывайте `http://localhost:3001` и используйте этот же порт в Postman. Остановка — `Ctrl+C`. После изменения frontend обновите страницу; после изменения backend перезапустите процесс. Можно использовать `npm run dev` для автоматического перезапуска backend.

## Что открыть рядом

- [Маршрут практики](TASKS.md) — пять этапов, около 50 минут.
- [Требования и API-контракт](CONTRACT.md) — источник ожидаемого поведения.
- [Шаблон отчёта](TESTING.md) — заполните своими наблюдениями.
- В браузере — приложение, **API-лаборатория**, DevTools → Network.

Интерфейс API-лаборатории позволяет вручную задавать метод, путь и JSON-тело. Она не проверяет ответы за вас. Для дополнительного балла есть [маршрут через Postman](POSTMAN.md).

## Исходное состояние

Внизу обеих страниц есть «Условия проверки». Нажмите **«Сбросить стенд»** перед началом независимого сценария:

- вернутся 3 исходные заявки;
- включится режим `normal`;
- удалится локальный черновик этого приложения;
- код и файл отчёта останутся без изменений.

Сброс удаляет ваши пробные заявки. Сначала сохраните нужные свидетельства.

Режимы ответа:

| Режим | Что происходит |
| --- | --- |
| `normal` | Обычные ответы API; намеренные дефекты продукта остаются |
| `delay` | Перед обработкой запроса к заявкам добавляется 1,5 секунды |
| `empty` | GET списка возвращает пустой массив; сохранённые записи не удаляются |
| `error` | Запросы к заявкам получают контролируемый HTTP 500 |

Режим применяется к следующему запросу и действует для UI, API-лаборатории и Postman. После переключения повторите действие. Искусственный 500 сам по себе не является дефектом: проверяйте реакцию интерфейса.

Каждый студент запускает свою копию сервера. Все вкладки на одном адресе используют одну базу. Не запускайте два процесса из одной папки. Используйте один адрес (`localhost`), не переключаясь на `127.0.0.1`: у них разные browser storage.

## Результат основной практики

В `TESTING.md`:

- чек-лист минимум из 6 проверок с результатами;
- два коротких тест-кейса: один для UI, один для API;
- один полный баг-репорт и свидетельства по обоим направлениям;
- результат воспроизведения напарником;
- одно небольшое исправление и проверки после него;
- вывод о готовности продукта в несколько предложений.

Если самостоятельный патч не успели, возьмите у преподавателя исправленный вариант и сами проведите повторную проверку. В отчёте укажите, кто сделал исправление.

Сохраняйте работу обычным способом в своём репозитории. Для показа достаточно отчёта, изменённого файла и воспроизведения в браузере; публикация backend не требуется.

## Файлы

```text
frontend/          интерфейс, браузерный API-клиент и управление условиями
backend/server.mjs моковый HTTP-сервер
backend/data/      исходные вымышленные данные
.runtime/          рабочие данные сервера; создаются при первом запуске
postman/           необязательная коллекция запросов
```

Для исправления выберите маленькое изменение в HTML/CSS/JS. Не переписывайте весь проект и не меняйте требования под фактическое поведение.

## Если запуск не удался

- `node` или `npm` не найдены: сообщите преподавателю и начните проверку на компьютере напарника.
- `EADDRINUSE`: остановите старый процесс или выберите другой порт.
- В браузере ошибка подключения: проверьте, что терминал сервера остаётся открытым.
- `.runtime/db.json` повреждён: остановите сервер, сохраните файл для диагностики, удалите только этот файл и запустите снова.

Используйте вымышленные имена и адреса `example.com`. Проверяем только этот учебный стенд.
