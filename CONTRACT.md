# Требования к «Веб-мастерской»

Это источник **ожидаемого** поведения. Реализация версии `workshop-1.0` может нарушать эти требования. Подтверждайте нарушения наблюдениями.

## Пользовательские требования

| ID | Требование |
| --- | --- |
| R1 | В режиме normal список показывает по одной карточке на каждую заявку из GET. Повторное обновление не создаёт дубли. Пустой ответ имеет отдельное понятное состояние |
| R2 | Все поля обязательны. Имя после удаления крайних пробелов содержит 2–60 символов. Email после удаления крайних пробелов имеет вид `name@example.com`, без пробелов, максимум 120 символов. Тема выбрана из списка. Неверная форма не отправляет POST |
| R3 | Сохранённые значения отображаются без подмены. Тема `html` означает «HTML и CSS», `javascript` — «JavaScript и DOM», `api` — «HTTP и API» |
| R4 | При отправке виден процесс, повторная отправка заблокирована. Успех показывается после успешного ответа; форма очищается. При ошибке введённые данные остаются, повтор доступен, ложного успеха нет |
| R5 | Кнопка сохранения черновика сохраняет поля в этом браузере; перезагрузка их восстанавливает. «Удалить черновик» очищает поля и сохранённые данные. Черновик и запись на сервере независимы |
| R6 | Кнопки и поля доступны через Tab; Enter отправляет корректную форму. На ширине 360 px основная кнопка доступна без горизонтальной прокрутки страницы |
| R7 | Успешный POST создаёт одну запись с уникальным id. В режиме normal последующие GET списка и GET по id возвращают эту запись с теми же значениями. Запись сохраняется при перезагрузке страницы и перезапуске сервера |
| R8 | Каждый объект заявки в списке и в ответе по id содержит все обязательные поля: id, name, email, topic, createdAt |

Неизвестная тема — ошибка ввода, а не новая категория. В этой версии нет редактирования, удаления отдельных заявок, авторизации или проверки доставки email.

## HTTP API

Базовый адрес по умолчанию: `http://localhost:3000`.

| Метод и путь | Тело | Ожидаемый ответ |
| --- | --- | --- |
| `GET /applications` | Нет | `200`, массив заявок |
| `GET /applications/:id` | Нет | `200`, объект заявки; `404`, если id отсутствует |
| `POST /applications` | JSON с name, email, topic | `201`, созданный объект с новым id |

Корректный запрос:

```http
POST /applications
Content-Type: application/json
```

```json
{
  "name": "Анна",
  "email": "anna@example.com",
  "topic": "html"
}
```

Форма успешного ответа:

```json
{
  "id": "4",
  "name": "Анна",
  "email": "anna@example.com",
  "topic": "html",
  "createdAt": "2026-10-20T10:00:00.000Z"
}
```

`id` — строка, `createdAt` — строка даты ISO 8601; сервер создаёт оба поля. Конкретные id и время зависят от запуска. Не проверяйте совпадение со временем примера. Значения name/email нормализуются удалением крайних пробелов. Повторный корректный POST с теми же данными создаёт новую заявку: запрета одинаковых email в этой версии нет.

## Ошибки

| Статус | Условие |
| --- | --- |
| `400` | Некорректный JSON, неверное поле или неизвестная тема |
| `404` | Заявка или маршрут не найдены |
| `405` | Метод не поддерживается для ресурса |
| `413` | Тело больше 64 КиБ |
| `415` | Для POST не указан `Content-Type: application/json` |
| `500` | Искусственный сбой в режиме error |
| `409` | Во время незавершённого запроса выполнен сброс стенда |

Форма ошибки:

```json
{
  "error": {
    "code": "INVALID_NAME",
    "message": "Имя должно содержать от 2 до 60 символов"
  }
}
```

Невалидный POST не добавляет запись. Проверяйте это последующим GET, а не только по статусу.

## Условия воспроизведения

- После сброса: mode=`normal`, 3 заявки с id `1`, `2`, `3`.
- Режим `delay` добавляет 1,5 секунды; результаты сравниваются после завершения запроса.
- Режим `empty` подменяет только ответ GET списка на `[]`; базу он не очищает.
- Режим `error` возвращает HTTP 500 для операций с заявками; переключатели стенда продолжают работать.
- Сброс удаляет пробные записи и локальный черновик в том браузере, где нажата кнопка. В другом браузере черновик очищается отдельно.
- При перезапуске сервер читает `.runtime/db.json`; режим возвращается в normal.
- При сравнении UI и API используйте одну версию, режим и исходные данные.

Служебные маршруты `/lab/state`, `/lab/config`, `/lab/reset` управляют условиями. Их реализацию в основной практике не тестируем. В ответах API есть `X-Lab-Version` и `X-Lab-Mode` для записи условий в отчёт.
